## The thesis, in one paragraph

Technographic data is sold as fact and consumed as fact — `technologies: ["Segment", "Snowflake",
"Intercom"]` — when every entry is really an **inference from an observation on a named surface**.
A script tag that is loading is a runtime artifact; a job posting asking for three years of
Databricks is a sentence in a different tense; a logo in an integrations directory is a purchase
order. This repo keeps the observation, the surface, the **reach** (a CDP tag on the marketing
site proves *marketing* bought a CDP) and the age attached to the claim all the way to the screen.
The sharp end is **negation**: the most valuable technographic queries are negative, and "not
detected" is only "does not use" when the technology would necessarily have appeared on a surface
you actually inspected. Chat widgets would; warehouses never will. So `not(Intercom)` is
computable and `not(Snowflake)` is not, and this is the only tool in the category that says so
out loud instead of silently returning the whole database. Sibling repos own the neighbours —
Day 001 `icp-score` owns weighted arithmetic, Day 005 `signal-scout` owns event derivation,
Day 006 `account-brief` owns span provenance, Day 007 `why-now` owns argument validity.
**Do not rebuild any of them here.** Day 008's only claim is epistemic status.

## Commands

Land these in `package.json` at scaffold time; they mirror Days 001–007 so a reviewer types the
same thing in every repo.

```bash
npm run dev                      # dev server
npm run build                    # production build — run before claiming done
npm test                         # vitest run (globs lib/**/*.test.ts only)
npm run test:watch               # watch mode
npm run sweep                    # invariant sweep, 14 companies × 32 technologies × 5 as-of dates, no network
npm run typecheck                # next typegen && tsc --noEmit
npm run lint                     # eslint (includes the engine boundary rule)
npx vitest run lib/technographics/resolve.test.ts     # single file
npx vitest run -t "vestigial"                         # single trap by name
```

`npm` is the committed package manager — README and lockfile stay npm even if bun is used
locally, because `npm install && npm run dev` is what a reviewer types without reading.

Five setup facts inherited from Days 001–007:

- Vitest config belongs in `vitest.config.mts` (`.mts`, not `.ts` — the extension is what stops
  Vite's config loader warning about ESM-in-CJS), and it globs `lib/**/*.test.ts` only. Tests
  outside `lib/` will not run.
- `tsc` alone fails on a clean checkout because `LayoutProps` and friends are generated into
  `.next/types`, so `typecheck` must run `next typegen` first. Never "fix" that error by editing
  `app/layout.tsx`.
- `tsconfig.json` sets `noUncheckedIndexedAccess` on top of `strict` — array and record access
  yields `T | undefined`. Handle it; do not reach for `!`.
- Scripts run through `vite-node -c vitest.config.mts` rather than bare `node`, because the engine
  uses extensionless relative imports that Node's ESM resolver rejects and the `@/` alias lives in
  the Vitest config.
- `AGENTS.md` is regenerated by `next dev`. Commit it with your work; deleting it from a diff only
  re-creates the uncommitted change.

## Architecture

```
                    ┌─ server component ─► data/*.ts (Zod-validated at import)
Browser ────────────┤
                    ├─ lib/technographics (pure) ─► same functions run client- and server-side
                    │
                    ├─ POST /api/translate  ─► key check ─► rate limit ─► model ─► Zod ─► query (unrun)
                    └─ POST /api/inspect    ─► robots ─► fetch ─► lib/technographics/detect
```

`lib/technographics/` is the engine and is **dependency-free and framework-free** — it imports
`zod` and nothing else. Not `next`, not `react`, not `@/data`, not `@google/genai`, no DOM
globals. An eslint `no-restricted-imports` rule scoped to that directory enforces it and the
package carries its own `README.md`. This is not stylistic: a module that cannot import a model
client cannot invent a detection, so every claim on screen came from an observation that was
passed in as an argument.

| module | responsibility |
|---|---|
| `types.ts` | the type contract — surfaces, grades, states, claims, predicates, tiers |
| `schema.ts` | Zod schemas for corpus and query; parsed at import, throws on bad data |
| `surfaces.ts` | six surfaces: `reach`, `halfLifeDays`, `exhaustive` |
| `graph.ts` | 8 categories, 32 technologies, four relations, the dark set |
| `detect.ts` | observation → evidence (which rule fired, on which surface) |
| `grade.ts` | `(kind, surface, age)` → grade, decay, expiry |
| `resolve.ts` | claims: four states, contradiction, migration, vestigial, implied |
| `query.ts` | predicate evaluation, minimum-confidence thresholds, computability |
| `tier.ts` | account × query → exactly one of five tiers |
| `export.ts` | CSV serialisation and permalink encode/decode |

`data/` holds the corpus (14 companies, ~120 observations), the technology graph and the
presets. `lib/translate/` holds the Gemini call, prompt, response schema and rate limiter.
`lib/inspect/` holds fetch, robots handling and timeouts. `app/` is the single console.

**The engine ships to the browser.** Moving the as-of date must re-resolve every claim without a
round trip. Nothing about a claim requires a server.

**Surfaces, technologies and relations are data, not code.** If you find yourself writing
`if (technologyId === "snowflake")` inside `lib/technographics/`, the fact belongs in `data/`
as a field on the record instead.

## Rules that are easy to break by accident

- **Never add a score.** Decision 12. No 0–100, no confidence float, no "match strength" that gets
  summed or sorted on. Grades are ordinal and derived from a declared lookup; results group into
  five tiers. A number is how this project turns back into Day 001.
- **Four states, not three.** `PRESENT` / `ABSENT` / `UNKNOWN` / `UNKNOWABLE`. Collapsing `UNKNOWN`
  ("nobody inspected a surface that would show it") into `UNKNOWABLE` ("no surface in the model can
  ever show it") destroys the entire thesis, because the first is fixable with more data and the
  second is not. The result tiers `INCONCLUSIVE` and `UNANSWERABLE` are the same distinction
  carried into the UI and must stay distinct too.
- **`absenceEstablishableOn` is the load-bearing field.** A technology gets `ABSENT` only when that
  list intersects the surfaces actually inspected *for that company*. Empty list ⇒ `not(...)` and
  `gap(...)` over it are uncomputable, and the query must **refuse** rather than return a fleet.
  Every warehouse and every reverse-ETL tool has an empty list, by construction.
- **`implies` never promotes a state.** A confirmed CDP implies a warehouse exists; the warehouse
  claim stays `UNKNOWABLE` with `impliedBy` set. Promoting it to `PRESENT` is exactly the vendor
  behaviour this repo exists to refuse. The sweep asserts it.
- **Reach is not confidence.** A `CONFIRMED` marketing-surface detection is confidently a fact
  about the marketing team. Do not let a high grade imply organisational breadth — render both.
- **Decay is monotone.** Confidence never improves as `asOf` advances. If a change makes an older
  as-of date produce a stronger claim, the change is wrong, not the invariant.
- **Grades come from a lookup table, not arithmetic.** `(evidence kind, surface, age)` → grade.
  No multiplying 0.7 by 0.8.
- **A negative statement is a contradiction, never support.** "We migrated off X" is evidence
  against X even when a stale tag for X is still loading. That pairing is the vestigial trap.
- **Two `CONFIRMED` competitors is a feature, not a data error.** It means `MIGRATING`, which is
  the single most actionable state in the product. Do not dedupe it away.
- **Presets 2 and 3 ship together.** The uncomputable gap (`reverse_etl`) and the computable gap
  (`support_chat`) are a matched pair — without the second, the refusal reads as a broken product
  instead of a principled one.
- **`/api/inspect` populates exactly two surfaces** — `page_markup` and `http_headers`. Everything
  else stays `UNKNOWN` and must never become `ABSENT`. One URL only; no link-following, no
  persistence, `robots.txt` honoured, 6s timeout, rate-limited. Widening this into a crawler is
  SSRF plus a licence problem.
- **The model never detects, grades, or resolves.** Its one job is prose → query object, which
  lands in the builder **unrun and editable**.
- **CSV keeps `UNKNOWN` as a value.** Exporting it as an empty cell re-creates the failure the
  whole repo is about.
- **The corpus is authored and synthetic.** Every domain ends in `.example`; no real company is
  described. Traps are named, and each has a test named after it.

## Gemini conventions (inherited from Days 001–007)

`@google/genai`, model `gemini-3.6-flash`, `responseMimeType: "application/json"` with a native
`responseSchema`, then Zod as the trust boundary — a schema is a request, a validator is a
guarantee. `ThinkingLevel.MINIMAL`: this is constrained translation against a fixed schema, not
reasoning. `temperature: 0`.

Missing key → **501** with a message pointing at the builder. Model failure → **502**. The app
must render all fourteen companies, every claim state, all four presets, the permalink and the CSV
with `GEMINI_API_KEY` unset.
